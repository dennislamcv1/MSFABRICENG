REAL-TIME FLEET INTELLIGENCE DASHBOARD
Solution Design and Performance Documentation
Meridian Logistics: 800 delivery vehicles across three regions, 20 August 2026

Timings and sizes below are illustrative.


1. REAL-TIME INTELLIGENCE
-------------------------

1.1 KQL: five-minute windowing

    VehicleTelemetry
    | where Timestamp > ago(24h)          // prunes extents first
    | where EngineTemp between (-40.0 .. 200.0)
    | summarize
          EventCount    = count(),
          AvgEngineTemp = avg(EngineTemp),
          MaxEngineTemp = max(EngineTemp),
          MinFuelLevel  = min(FuelLevel),
          FuelUsedPct   = max(FuelLevel) - min(FuelLevel)
      by VehicleID, WindowStart = bin(Timestamp, 5m)

ago() resolves at query start, so filtering on it first discards whole extents
unread. bin() floors event time into fixed, non-overlapping buckets, making
results repeatable - and materializable as view TelemetryRollup5m, turning 6.9M
raw rows a day into 230,400.

1.2 Eventhouse table: VehicleTelemetry

  Column       Type      Purpose
  VehicleID    string    Natural key; joins DimVehicle, group-by for rollups
  Timestamp    datetime  Device event time; all bin()/ago() windowing uses it
  Latitude     real      Position north-south; feeds the map
  Longitude    real      Position east-west; validated with Latitude
  EngineTemp   real      Coolant deg C; window max drives overheat alerts
  FuelLevel    real      Tank percent; window max-minus-min proxies usage

1.3 Eventstream. Source: Azure IoT Hub, for device identity and twins.
Transformations, as event processing before ingestion: cast Timestamp and
numerics to real types; drop null keys, null coordinates and out-of-range
sentinels; reject clocks over 24 hours from ingestion. Rejects are quarantined,
not deleted. Destination: Eventhouse table VehicleTelemetry.

1.4 Retention

    .alter-merge table VehicleTelemetry policy retention
        softdelete = 90d recoverability = enabled
    .alter table VehicleTelemetry policy caching hot = 14d

    .alter-merge materialized-view TelemetryRollup5m policy retention
        softdelete = 730d recoverability = enabled

Raw telemetry 90 days - a quarter of incident and warranty work - 14 days hot.
The rollup 730 days, so year-over-year comparison survives at a thirtieth of the
storage. The KQL default is 3,650 days; set it explicitly.


2. SEMANTIC MODEL
-----------------

2.1 Tables. Fact FactDeliveries, grain one completed delivery, 10.4M rows:
DeliveryID (hidden integer, not the source GUID), DateKey, PromisedDateKey,
VehicleKey, RouteKey, DeliveryTime, PlannedTime, Distance, FuelUsed, OnTimeFlag.
Dimensions: DimDate (1,461 rows, contiguous, marked as a date table), DimVehicle
(800), DimRoute (40).

2.2 Relationships - all many-to-one fact to dimension, single direction.

  FactDeliveries[DateKey]         -> DimDate[DateKey]        active
  FactDeliveries[VehicleKey]      -> DimVehicle[VehicleKey]  active
  FactDeliveries[RouteKey]        -> DimRoute[RouteKey]      active
  FactDeliveries[PromisedDateKey] -> DimDate[DateKey]        inactive
  LiveVehicleStatus[VehicleID]    -> DimVehicle[VehicleID]   limited

Many-to-one lets the engine use its relationship index. Single direction keeps
filter paths unambiguous - two paths reach DimDate - and avoids materialising
fact-side values, worth 340 ms. PromisedDateKey is role-playing, activated by
USERELATIONSHIP.

2.3 Hierarchies. Calendar: Year > Quarter > Month > Day, with sort-by columns so
months order chronologically and auto date/time off; plus Region > Depot >
Vehicle for the map and matrix drill-down.

2.4 Field parameter

    Metric Selector = {
        ("Average Delivery Time",   NAMEOF('_Measures'[Avg Delivery Time]),  0),
        ("Total Distance",          NAMEOF('_Measures'[Total Distance]),     1),
        ("Average Fuel Efficiency", NAMEOF('_Measures'[Fuel Efficiency]),    2)
    }

One trend visual serves all three metrics via a single-select list slicer: one
query per load, not three.


3. DAX OPTIMISATION
-------------------

3.1 Measures. A measure reference inside a row context forces context transition
per row.

    Fuel Efficiency (slow) =
    AVERAGEX ( FactDeliveries, DIVIDE ( [Total Distance], [Total Fuel Used] ) )

    Fuel Efficiency =
    VAR DistanceKm = SUM ( FactDeliveries[Distance] )
    VAR FuelLitres = SUM ( FactDeliveries[FuelUsed] )
    RETURN DIVIDE ( DistanceKm, FuelLitres )

Two storage-engine scans and one division, each VAR evaluated once: 588 to
138 ms.

    On-Time Delivery % =
    VAR TotalDeliveries  = COUNTROWS ( FactDeliveries )
    VAR OnTimeDeliveries = CALCULATE ( COUNTROWS ( FactDeliveries ),
                               FactDeliveries[OnTimeFlag] = 1 )
    RETURN DIVIDE ( OnTimeDeliveries, TotalDeliveries )

The comparison moves to the Dataflow; a two-value column is answered from the
dictionary: 655 to 155 ms.

    Worst Route Avg Delivery Time =
    MAXX ( VALUES ( DimRoute[RouteName] ),      -- 40 iterations, not 10.4M
        CALCULATE ( AVERAGE ( FactDeliveries[DeliveryTime] ) ) )

Iterate the smallest table that answers the question, using a column reference.

3.2 Time intelligence. YTD replaces the date selection with 1 January to the
last visible date: DATESYTD(DimDate[Date]). Prior Year shifts it back a year,
preserving shape: SAMEPERIODLASTYEAR(DimDate[Date]). YoY and YoY % are
arithmetic on those. All need DimDate marked as a date table.

3.3 Calculation group: 'Time Intelligence'[Time Calculation]

  Item     DAX expression                                     Format string
  Current  SELECTEDMEASURE()                                  inherited
  YTD      CALCULATE(SELECTEDMEASURE(), DATESYTD(...))         inherited
  PY       CALCULATE(SELECTEDMEASURE(), SAMEPERIODLASTYEAR(..)) inherited
  PY YTD   DATESYTD(SAMEPERIODLASTYEAR(...)) wrapper           inherited
  YoY      SELECTEDMEASURE() minus the PY item                 inherited
  YoY %    DIVIDE(YoY, PY)                                     "#,##0.0 %"

    // YoY %
    VAR CurrentValue = SELECTEDMEASURE ()
    VAR PriorYear = CALCULATE ( SELECTEDMEASURE (),
                        'Time Intelligence'[Time Calculation] = "PY" )
    RETURN DIVIDE ( CurrentValue - PriorYear, PriorYear )

SELECTEDMEASURE() is a placeholder the engine swaps for whichever measure the
visual displays, so one item covers every measure.
SELECTEDMEASUREFORMATSTRING() inherits that measure's format, so YTD distance
still renders as kilometres; YoY % overrides it, since inheriting "#,##0 km"
would show 4.2 % as 0 km. YoY and YoY % call the PY item by name, so a
fiscal-calendar change is one edit. Six items replace 25 measures.

3.4 DAX Studio Server Timings, ms (illustrative)

  Measure                Total     FE  FE share    SE  SE queries
  YoY by Month  before   4,180  3,286      79%   894       1,412
  YoY by Month  after      585     96      16%   489           4

A formula-engine share above half signals row-by-row work; hundreds of tiny
storage-engine queries are the CallbackDataID signature of context transition.


4. PERFORMANCE TUNING
---------------------

4.1 Incremental refresh. RangeStart and RangeEnd Date/Time parameters filter
DeliveryDateTime with >= RangeStart and < RangeEnd, placed first so the
predicate folds to SQL. Archive three years, refresh the last 10 days, detect
data changes on ModifiedDate, only refresh complete days. Nightly, only the two
to four daily partitions whose MAX(ModifiedDate) moved are reprocessed:
47 min 20 s becomes 2 min 51 s.

4.2 Aggregation table. AggDeliveriesDayRoute, Import, hidden, grouped by DateKey
and RouteKey: 43,840 rows against 10.4M, 237:1, for 1.8 MB. Manage Aggregations
maps both keys as GroupBy; Distance, FuelUsed, DeliveryTime and OnTimeFlag as
Sum; DeliveryTime as Max; Count table rows. Date- and route-grain queries hit
it; vehicle-grain queries fall back to the fact table.

4.3 Performance Analyzer, Executive Overview, ms (illustrative)

  Visual                          Baseline    After
  KPI cards (four)                   2,585      764
  Line, Delivery Time YoY            4,485      783
  Column, Distance by Region         1,566      365
  Map, Live Vehicle Positions        2,378      862
  Table, Route Detail Top 20         1,275      520
  Slicer, Vehicle/Region             1,475       95
  Slicer, Date range                   325      166
  PAGE TOTAL                         7,240    2,910

Slowest baseline visual: the YoY line chart, 4,485 ms, of which 4,180 ms was
query time - a DAX bottleneck, not display or other. Cause: AVERAGEX over the
fact table with nested measure references, run per month across 36 months. The
rewrite, calculation group and aggregation took it to 783 ms; the map is now
slowest, at 862 ms, bottlenecked on Other.

4.4 Optimisation summary

  DAX rewrites removing context transition       -1,821 ms
  Live map bound to a KQL function               -1,516 ms
  800-item slicer replaced by region tile        -1,380 ms
  Aggregation table                              -1,201 ms
  Four charts consolidated into one                -900 ms
  Calculation group                                -310 ms
  DeliveryID as integer, not GUID                    -71 MB
  Unused columns and auto date/time removed         -107 MB
  Incremental refresh                           -44 min 29 s

Model 486 MB to 291 MB; DeliveryID is the largest saving because VertiPaq cost
scales with cardinality, not row count. Per-visual savings exceed the page gain
because visuals evaluate in parallel: the page total is the critical path.


5. DASHBOARD ARCHITECTURE
-------------------------

5.1 Pages. Executive Overview (landing: four KPI cards, field-parameter trend,
regional column chart, worst-routes table); Live Fleet Map, the only DirectQuery
page; Delivery Performance (matrix with the calculation group on columns,
decomposition tree, waterfall); Route Analysis (scatter, small multiples,
Top 20); Vehicle Detail, a hidden drill-through target on DimVehicle[VehicleID].
Navigation: page-navigation bookmark buttons, page tabs and back buttons. No
page mixes Import and DirectQuery visuals.

5.2 Visuals. Cards for KPIs (one number, under 50 ms). Line chart for trends:
slope encodes rate of change over ordered time. Clustered column for regions by
quarter: position on a common baseline is decoded most accurately. Azure Map for
latitude and longitude, coloured by health status. Matrix, uniquely combining
row drill-down with a calculation group on columns. Plus decomposition tree,
waterfall, scatter and Top N tables; gauges, pies and custom visuals rejected.

5.3 Slicers. Region and Time Calculation as tiles - three and six values, one
click, no dropdown. Date as a Between slider, not a 1,461-item list. Metric as a
single-select list driving the field parameter. The 800-item Vehicle slicer was
deleted in favour of drill-through, and Top N caps the route table at 20.
Apply-all-slicers is on, so a two-slicer change fires one query round.

5.4 Real-time integration. A composite model: history in Import, plus
LiveVehicleStatus in DirectQuery against the Eventhouse, bound to a stored KQL
function returning at most 800 rows rather than raw telemetry. Automatic page
refresh, fixed 5-minute interval, on the DirectQuery page only - it has no
effect on Import pages. Change detection was rejected: at one reading per
vehicle per 10 seconds it fires every poll.

5.5 Load time. Executive Overview, cold cache, three-year range, median of five
runs: 2,910 ms against a 4,000 ms target - 27 percent headroom.
